# Richtlijn: website changelog per iteratie

Deze richtlijn borgt dat de changelog op de About-pagina na elke iteratie bruikbaar is voor eindgebruikers.

## Verplicht per iteratie
- Voeg minimaal een nieuw changelog-item toe voor de afgeronde iteratie.
- Schrijf in duidelijke, niet-technische taal.
- Benoem functioneel wat er is verbeterd voor de gebruiker.

## Format per changelog-item
- Iteratie: nummer of label van de iteratie.
- Datum: opleverdatum van de iteratie.
- Titel: korte, duidelijke samenvatting van de verbetering.
- Highlights (2-4 bullets):
  - Wat is er nieuw of aangepast?
  - Wat merkt de gebruiker daarvan in de praktijk?

## Schrijfstijl
- Gebruik korte zinnen en vermijd intern technisch jargon.
- Focus op gebruikswaarde, niet op implementatiedetails.
- Voorbeeld van goed: "Je kunt nu direct in het menu naar Admin om rollen te beheren."
- Voorbeeld van minder goed: "RBAC-autorisatie toegevoegd met nieuwe endpoint-guards."
